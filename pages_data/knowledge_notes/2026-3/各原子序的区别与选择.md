# 各原子序的区别与选择

原子变量的内存序（memory order）决定了：

- 这次原子操作对别的线程可见的顺序
- 编译器/CPU 允许做多大程度的重排序
- 能不能建立 **happens-before** 关系

在 C++ 里常见的有：

- `memory_order_relaxed`
- `memory_order_acquire`
- `memory_order_release`
- `memory_order_acq_rel`
- `memory_order_seq_cst`

## 怎么设定

以 `std::atomic` 为例：

```cpp
std::atomic<int> x{0};

x.store(1, std::memory_order_release);
int v = x.load(std::memory_order_acquire);
```

或者：

```cpp
x.exchange(1, std::memory_order_acq_rel);
```

还有：

```cpp
x.fetch_add(1, std::memory_order_relaxed);
```

## 各种内存序的含义

**relaxed**：

- 只保证原子性
- 不保证和其他内存操作的顺序
- 适合：计数器、统计值、无同步语义的状态

**release**：

- 适合写入方
- 保证该线程在这之前的写操作，不会被重排到这次 store 之后
- 常用于“发布数据”

**acquire**：

- 适合读取方
- 保证这次 load 之后的读写，不会被重排到它之前
- 常用于“获取已发布的数据”

**acq_rel**：

- 同时具备 acquire + release
- 常见于 RMW 操作，如 exchange、fetch_add

**seq_cst**：

- 最强语义
- 所有 seq_cst 操作看起来有一个全局统一顺序
- 最好理解，但性能通常更保守

## 怎么选择

**场景一**：只计数，不同步其他数据

```cpp
counter.fetch_add(1, std::memory_order_relaxed);
```

用 `relaxed` 就够了。

---

**场景二**：一个线程写数据，另一个线程读标志后使用数据

典型“发布-订阅”模式：

```cpp
// 线程B
data = 42;
ready.store(true, std::memory_order_release);

// 线程A
while (!ready.load(std::memory_order_acquire)) {}
use(data);
```

这里必须配对：

- 写线程：`release`
- 读线程：`acquire`

这样 A 看到 `ready == true` 时，也能看到 B 在此之前写入的 `data = 42`。

---

**场景三**：只想简单粗暴，先写对再说

```cpp
store/load 都用 seq_cst
```

优点：

- 最容易写对
- 调试友好

缺点：

- 可能比需要的更慢

## 选择原则

1. 先想语义

    - 你是要“计数”？
    - 还是要“通知数据已准备好”？
    - 还是要“互斥访问”？

2. 能用 relaxed 就别升级

    - 如果不依赖同步，只要原子性，就用 relaxed

3. 有发布/消费关系就用 release/acquire

    - 这是最常见、最实用的模式

4. 不确定时先用 seq_cst

    - 保证正确
    - 性能以后再优化

## 实用的记忆法

- 只看数字/计数 -> `relaxed`
- 发信号/发布结果 -> `release` / `acquire`
- 读写都复杂、不想想太多 -> `seq_cst`
